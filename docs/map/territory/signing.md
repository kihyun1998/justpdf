# Digital signing (CMS, ByteRange)

## What it is
`sign_pdf` leaves the original bytes untouched and appends an incremental section holding a signature dictionary with a `/Contents` placeholder, a signature field merged with its widget, for a visible signature its appearance stream, and new revisions of the objects that link the field into the document. It then fills in `/ByteRange`, takes the digest of the bytes outside the `/Contents` string, builds a CMS SignedData (`/SubFilter /adbe.pkcs7.detached`, RSA PKCS#1 v1.5) over it by hand-written DER, and writes it into the placeholder as hex. Nothing in the product calls it: CLI `sign` is a stub and the facade has no signing call.

## Governing decisions
**None.** Refusing encrypted input is a maintainer decision (#26): `sign_pdf` takes no password, so there is no key to encrypt the appended objects with.

## Design model
From reading the source (`sign/sign_pdf.rs`), the tests named, probes on 2026-10-30 (OpenSSL 3.6.4) and on 2026-11-01 (OpenSSL 4.1.0, poppler `pdfsig` 26.06.0), each with a throwaway RSA-2048 key and a self-signed certificate. Unlabelled facts below are read from the code (inferred).
- **Inputs**: a PKCS#8 DER RSA key (other key types are refused at parse), DER certificates with the signer first, `SigningOptions`. Encrypted input is refused with `UnsupportedEncryption` (`test_placeholder_rejects_encrypted_input`).
- **Placeholder** (`Placeholder`): `/Contents` is `PLACEHOLDER_SIZE` (16,384) bytes, written as 32,768 hex zeros between `<` and `>`; a CMS blob larger than that is an error. `contents_offset` is the `<` and `contents_length` counts both delimiters, so the `/ByteRange` hole is exactly the hex string, delimiters included, as ISO 32000-1 §12.8.3.3.1 requires ("It shall fit precisely in the space between the ranges", read raw in Adobe's `PDF32000_2008.pdf` on 2026-11-01). Before #408 the hole started after `<`, so both delimiters were signed (measured 2026-11-01).
- **Order of the steps** (`sign_pdf`, #408): `build_pdf_with_placeholder` records where the `/ByteRange` array starts (`byte_range_offset`). `sign_pdf` writes the real values there in the placeholder's width (`{:010}`), then takes the digest, then writes the CMS hex between the delimiters. The digest therefore covers the file as written. A value of more than ten digits, from an output of 10^10 bytes or more, is a `SignatureError` rather than a write over `/Contents` (`BYTE_RANGE_PLACEHOLDER`; inferred, since a test would need a 10 GB input). The appended xref entries have the same ten-digit limit and no such check (inferred). Before #408 the digest was taken while `/ByteRange` still read zeros, and `fix_byte_range` then wrote the real values inside the signed ranges, at the first match of the placeholder text anywhere in the file. `openssl cms -verify` failed over the final file's ranges and succeeded with the placeholder text put back; it now succeeds over the file (OpenSSL 4.1.0, a throwaway RSA-2048 key, *measured* 2026-11-01). Pinned by `tests/sign_roundtrip.rs`, which signs `minimal.pdf` with `tests/fixtures/sign_test_key.der` and `sign_test_cert.der` (made with OpenSSL for the tests) and verifies the padded `/Contents` with `verify_signature`. Taking the digest before writing the values, or putting the delimiters back inside the ranges, each failed a named test (*measured* 2026-11-01).
- **Linked into the document** (`link_field`, #37; the behaviour is *measured* by the tests named below). The field's reference is appended to `/AcroForm /Fields`; when the catalog has no `/AcroForm`, one is created. An indirect `/Fields` is written out as a direct array, because [Signature detection](signature-detection.md) and `parse_acroform` read only a direct one. `/SigFlags` gets bits 1 and 2 (SignaturesExist, AppendOnly; ISO 32000-1 Table 219, read raw) on top of what it had. The reference is also appended to the `/Annots` of the page `SigningOptions::page` names (0-based; past the last page is `PageOutOfRange` and nothing is written), and the widget's `/P` points at that page. Each object the change lands in gets a new revision at its own number and generation: the catalog for a direct or absent `/AcroForm`, the `/AcroForm` object for an indirect one, the page for a direct or absent `/Annots`, and the array object for an indirect one. An indirect `/AcroForm` or `/Annots` is revised at its own number only when it resolves to a dictionary or an array; an undefined object (null) or one of the wrong kind reads as absent and the catalog or page is revised instead, so a reference at a generation the object lacks, or naming the catalog, no longer gets the page tree or catalog overwritten (`references_to_nothing_or_the_wrong_kind_are_not_revised`; found in review, where `/Annots 2 1 R` had replaced the page tree, *measured* 2026-11-01). The field is named `SignatureN`, the first N no top-level field's `/T` (read as a text string, UTF-16BE included) uses, so signing a signed file adds `Signature2` (*measured*, tests below).
- **Entries of the signature dictionary** (*measured*, `a_signature_is_detected_with_its_entries_and_verifies`): `/Name` (default `justpdf`), `/M` as a PDF date `D:YYYYMMDDHHmmSSZ` from the same instant as the CMS signingTime (`SigningTime`), `/Reason` and `/Location` when not empty, and `/ContactInfo` when set.
- **Measured** (2026-11-01): `detect_signatures` finds the signature with its field name and entries, and `verify_signature` reports the digest and the signature value valid (`tests/sign_wiring.rs`). poppler `pdfsig` 26.06.0 lists `Signature1` on a signed `minimal.pdf`, and both signatures on a file signed twice (the second visible), each "Signature is Valid", the first "Not total document signed" after the second revision, with "Certificate issuer isn't Trusted" for the self-signed test certificate. Each of these mutations failed a named test in `tests/sign_wiring.rs`: numbering from the entry count, not appending to `/Annots` or `/Fields`, dropping the existing fields or annotations, not setting `/SigFlags`, always naming `Signature1`, leaving out `/M`, `/ContactInfo` or `/P`, ignoring `page`, or keeping `/Fields` indirect.
- **Widget**: a visible one gets `/Rect` (default `[0 0 200 80]`), `/AP /N` and `/F 4` (Print); an invisible one gets `/Rect [0 0 0 0]` and `/F 132`, Print + Locked (bits 3 and 8, ISO 32000-1 Table 165, read raw on 2026-11-01).
- **Object numbers**: the new objects are numbered from the highest number the source uses plus 1, as `DocumentModifier::from_document` does (#37). Before #37 they started at the xref entry count plus 11, so a file with objects 1–3 and 16 had its object 16 replaced by the signature dictionary (`new_objects_are_numbered_above_every_existing_number`, which failed with the old rule, *measured* 2026-11-01). The xref lists every new and revised object in number order, and the trailer `/Size` is at least the highest plus 1.
- **Values in the appended objects** are written with shared functions: `/Name`, `/M`, `/Reason`, `/Location`, `/ContactInfo` and `/T` with `string_syntax` (the UTF-8 bytes of a `&str`, hex when not printable ASCII), `/Rect` with `real_syntax` (NaN → `0.0`, ±∞ → ±`f32::MAX`), the appearance dictionary with `serialize_dict` (`test_placeholder_values_read_back_unchanged`, #29), the revised objects with `serialize_object` — [Object syntax roundtrip](../invariant/object-syntax-roundtrip.md), [Text string encoding](../invariant/text-string-encoding.md).
- **Xref and trailer**: one subsection per new object with 20-byte entries (`test_placeholder_xref_entries_are_20_bytes`) — [Xref entry format](../invariant/xref-entry-format.md); the trailer from `incremental_trailer`, keeping the original trailer's keys (`test_placeholder_keeps_trailer_keys`) — [Incremental trailer](../invariant/incremental-trailer.md).
- **CMS**: signed attributes contentType, signingTime (UTCTime from the system clock, the same instant as `/M`) and messageDigest; the signer identified by issuer and serial; the whole certificate list in `certificates`; a caller's `SigningOptions::timestamp_token` added as an unsigned attribute ([Timestamps](timestamps.md)). DER lengths are written up to 3 bytes (`encode_der_length`).
- **Bounds on input**: the whole input file is parsed and copied, with a newline appended when it does not end in one; each top-level field in `/Fields` is resolved once to read its `/T`, and nothing recurses; the CMS size is bounded by the placeholder; signer name and reason lengths are not bounded. A source using object number `u32::MAX` is a `SignatureError` rather than an overflow (inferred, no test).

## Reference behaviour
- OpenSSL `cms -verify -binary -noverify` over the `/ByteRange` bytes: 3.6.4 verified only with the placeholder text put back (2026-10-30); 4.1.0 verifies over the file as written (2026-11-01, above).
- No comparison with Acrobat, pyHanko or MuPDF's signer is recorded. Clauses to compare against: ISO 32000-2 §12.8.1 (`/ByteRange`, `/Contents`), §12.8.3.

## Blast radius
- [Incremental save](incremental-save.md) — appends a revision by its own code; the two pick object numbers and build trailers separately, so a defect found on one side is looked for on the other.
- [Xref](xref.md) — reads the appended section through `/Prev`; an entry or `/Size` it misreads hides the signature objects.
- [Signature appearance](signature-appearance.md) — draws the visible signature from the signer name and reason passed here.
- [Timestamps](timestamps.md) — the token goes in as an unsigned attribute; it must cover the signature value made here (#180).
- [Signature detection](signature-detection.md), [Signature verification](signature-verification.md) — read what this writes: the field placement decides whether detection finds it, the padding and `/ByteRange` decide whether verification can pass.
- [CLI](cli.md) — `sign` refuses with "not implemented yet (#181)" and exit code 1; wiring it would ship the defects above.

## Known holes / open
- CLI `sign` does not sign. Tracked: #181 (keys and certificates), #308 (PKCS#12), #309 (`--timestamp-url`).
- Encrypted documents cannot be signed (above).
- A page object listed twice in the page tree gets one widget that shows on both pages (*measured* in review, 2026-11-01).
- The highest object number, when it is a free entry, is used again for the first new object, which ISO 32000-1 §7.5.4 forbids; `DocumentModifier` numbers the same way (*measured* in review: justpdf and `pdfsig` accept the result).
- Nothing in justpdf reads `/SigFlags`: a full rewrite (`DocumentModifier::build`, compression, redaction) of a signed file invalidates its signatures without a warning (inferred). Tracked: #463
- The CMS signingTime is a UTCTime for every year; RFC 5652 asks for GeneralizedTime from 2050 (inferred).
- Text strings are written as BOM-less UTF-8. Tracked: #33.

# Font subsetting

## What it is
Keeps only the glyphs the document actually uses from an embedded TrueType font (FontFile2) and reassembles the tables. Core's `subset_font` handles the font binary; on the compress side, `subset_embedded_fonts` collects the codes used in the document, decides which GIDs to keep, and replaces only the FontFile2 stream. The font dictionary (`/Widths`, `/CIDToGIDMap`, `/W`, `/Encoding`) is not touched. Compress is the only consumer.

## Governing decisions
**None.**

## Design model
- **GIDs are kept.** `subset_font` leaves `numGlyphs` as it is and makes the glyphs it does not keep zero-length (`loca` is always the long format). Component references in composite glyphs stay as in the original. `hmtx` keeps the original layout and zeroes the values of glyphs it does not keep — except the advance of the last long metric, which the glyphs after it share, so it is kept. `gid_map` is the identity mapping over the kept glyphs. CFF/`OTTO` fonts are refused.
  - So the font dictionary does not need fixing, and whichever path a viewer uses to find a glyph (which `cmap` subtable, `post` names, code = GID), the kept GIDs are unchanged.
  - Cost (measured 2026-09-23, "Hello" in Noto Sans compressed with `preset_medium`): subset font program Flate(9) size 28,278 B (renumbered, before #51) → 29,201 B (GIDs kept), +923 B. The whole output PDF went from 30,888 B → 32,185 B. The extra is `loca` repeating nearly the same value, `hmtx` that is mostly zeros, and the extra glyphs the union keeps. Most of the size at the time was `cmap` (12,760 B) and `post` (42,975 B) copied from the original unchanged — the `cmap` and `post` reductions below are that share.
- **`cmap` keeps only entries that go to kept glyphs** (`subset_cmap`). Encoding records keep their order, platform/encoding IDs and subtable sharing (in Noto, (0,3)/(3,1) and (0,4)/(3,10) each share one subtable). Formats 0 and 6 keep their layout and zero the dropped glyphs; formats 4 and 12 rewrite the mappings to kept glyphs (excluding 0) as one segment/group per contiguous run (code and GID both increasing by 1) (format 4 uses only `idDelta`, with every `idRangeOffset` 0). Other formats (2, 8, 10, 13, 14) are copied from the original unchanged — entries pointing at dropped glyphs may remain, but those glyphs are merely empty and the GIDs are right. An unparsable `cmap`, a format 4 over the 16-bit length (more than 8,189 segments), and a format 12 whose mappings exceed the number of Unicode code points (0x110000) also fall back to the original.
  - The cost of reading is bound to the kept glyphs, not the input: format 4 looks up codes 0..0xFFFE once each (ttf-parser), and format 12 reads the groups directly and maps back to codes only the kept GIDs each group covers (`format_12_kept_mappings`). Walking every code of a subtable (`codepoints`) is not used — a single group `[0, 0xFFFFFFFF]` in a malicious font becomes about 4.3 billion lookups, and overlapping format 4 segments going to glyph 0 collect tens of GB (estimated from reading code in review, 2026-09-29). The test checks that this group is handled within 1 second.
  - Trap: computing format 4's `searchRange` with `calc_table_search_params`, which is for the table directory (16-byte units, u16 multiplication), overflows from 4,096 segments on — a CJK document of a few thousand characters reaches that. Format 4 computes it with its own formula (`2 × 2^floor(log2 segCount)`).
  - Keeping every subtable pairs with #51's union approach: subsetting keeps the glyphs of every lookup path, so a viewer looking through any subtable must reach the kept glyphs.
- **`post` keeps only the names of kept glyphs** (`subset_post`). For format 2, `glyphNameIndex` stays at `numGlyphs` entries; dropped glyphs get 0 (`.notdef`), kept glyphs with a standard Macintosh name (<258) get that index, and the rest are renumbered into a new name list. Other formats (1, 2.5, 3, 4), broken tables, and cases with so many custom names that a new index would reach the reserved range (32768 and up) are left as in the original.
  - The kept names are always kept, whether or not there is a `/Differences` (derived, 2026-09-29, #69): the kept glyphs' names are the same as in the original, so a viewer that finds names through `post` does not break either, and going to format 3 (no names) would save only `numGlyphs`×2 B that are mostly zero (Noto 7,768 B, nearly 0 after Flate). This derivation made the conditional the issue proposed, "keep names when `/Differences` is used", unnecessary.
- Cost (measured 2026-09-29, same "Hello" input as above, compared with the same tree with `cmap` and `post` reverted to the original): subset font program 89,260 B → 41,572 B (decompressed), Flate(9) 29,201 B → 1,822 B. Whole output PDF 32,184 B → 4,803 B. Most of what remains of the decompressed size is `loca` 15,540 B, `hmtx` 15,536 B and the `post` index 7,810 B, nearly all zeros or repeated values, so small after Flate. `name` is 1,510 B.
  - **Maintainer decision (2026-09-29, #69)**: `name` is left as in the original. Facts presented: MuPDF's `subset_name_table`, read from the source, drops no records at all (`filter_name_tables` is `/* FIXME: For now, we keep everything. */ return 1;`) and only merges identical strings — the issue body's "MuPDF reduces it" is true only to that extent. Size 1,510 B. Alternatives were "only merge duplicate strings" (MuPDF's level) and "keep only the required name IDs" (no precedent in a reference implementation). This decision did not cover `OS/2`, `cvt `, `fpgm`, `prep`, or dropping `cmap` and `post` entirely from CID fonts (Known holes below).
  - **Maintainer decision (2026-09-23, #51)**: keeping GIDs was chosen. The alternative presented was MuPDF's simple-font approach (renumbering + regenerating one `cmap` subtable and `post`, rewriting `/CIDToGIDMap` for CID) — slightly smaller, but it breaks in viewers that look through other subtables or `post` names, and it is more to implement. Facts presented as grounds: Ghostscript keeps GIDs, and MuPDF keeps them for CID fonts too (Reference behaviour below).
- **The unit of subsetting is the FontFile2 stream.** Candidate fonts are grouped by the FontFile2 object they reach; each stream is cut once, keeping the union of the glyph IDs every font in the group picks from the **original** program. `fonts_subsetted` counts replaced streams.
  - The stream is left whole when any font in the group trips the safety guard below or cannot resolve its glyphs (`simple_font_glyph_ids`/`cid_font_glyph_ids` return `None`), or when **the chain is not closed**: something other than the grouped fonts and the objects between them and the stream (the FontDescriptor, and for CID the descendant CIDFont) references the stream or one of those objects. A non-candidate font sharing the program (one drawn only inside a form XObject, or never drawn on a page) and a font reaching it through an inline FontDescriptor are caught here. A group whose fonts all showed only empty strings is left alone.
  - Why (measured, 2026-09-30, #117): subsetting once per font dictionary let the next font read back the stream `set_object` had just replaced and cut it again. With two fonts sharing a program and drawing "H" and "o", **both** lost their outlines — the second font could not find its character in the `cmap` #69 had already cut and picked only the code-as-GID glyph. Ghostscript rendered "Hello" + "world" as `llo  o l`; after the change the render is pixel-identical to the input. A font left whole on purpose (shown with `"`) lost its glyphs when a sibling cut the shared stream. The guard was per font while the cut is on the shared stream, so the decision moved up to the stream.
  - Because glyph IDs are kept (#51), a simple font and a CID font sharing one stream are served by the plain union of their glyph IDs (inferred).
- **Choosing GIDs to keep — simple TrueType** (`simple_font_glyph_ids`): for each code used, keep the **union** of `font::truetype_glyph_candidates` — the renderer's rule plus every fallback ([Font encodings](font-encodings.md)). The font's `/Encoding` (resolved when indirect) is read with `parse_font_info`. Since GIDs are kept, the union is right regardless of which path a viewer takes.
  - The font is **kept whole** only when, in a **non-symbolic** font, a used code's `/Differences` name is found by neither `post` nor the Unicode the AGL gives it. A symbolic font's glyph is chosen by code through (3,0)/(1,0), not by name (§9.6.6.4, pdf.js), so its names are not checked — derived from the rule, and confirmed by the maintainer in #223 (2026-10-07) over the brief's "keep today's rule". Until #223 (absorbing #118 and #269) a name was resolved without the AGL, symbolic fonts were checked too, and a non-symbolic font with a non-WinAnsi base using codes `0x80` and up was kept whole.
  - Measured 2026-10-07, `justpdf compress --font-subsetting` on the PDFs in the repository root and the CLI/core fixtures (13 files): before #223 the keep-whole branch fired in the 6 files of the brochure family, 4 fonts each — all symbolic (3,0) fonts with a WinAnsi base whose `/Differences` names (`quotedblleft`, `g17`, `g395`, …) had no `post` entry; none on the high-code branch. After: 0. The bytes it cost: none — those fonts were already subset by their producer, and `subset_font` makes them larger (8,996 → 11,444, 30,496 → 44,740, 36,476 → 50,500, 36,928 → 50,748 bytes), so the original is kept and every output size is unchanged.
- **Choosing GIDs to keep — CID** (`cid_font_glyph_ids`): only `Identity-H`/`V` are subsetted, and CID → GID goes through `/CIDToGIDMap` (absent or `Identity` means CID = GID; a stream is a table; a CID outside the table is GID 0). Any other CMap or an unreadable table keeps the font whole.
- **Safety guard for gaps in collection**: used codes are collected only from `Tj`/`'`/`TJ` in page content. So a font that may also be used where collection cannot see is not subsetted (`fonts_reachable_outside_page_resources`) — when something other than the page itself (inline `/Resources`, `/Font`), the page's indirect `/Resources` or its `/Font` dictionary references the font (a Form XObject, an annotation appearance, `/Resources` inherited from the page tree, AcroForm `/DR`). A font drawn with the `"` operator is not subsetted either.
  - **Maintainer decision (2026-09-23, #51)**: fixing the collection itself (a content walker) is left to a separate issue, and this safety guard stands in the meantime. The alternatives "include it in #51" and "separate issue only (no safety guard)" were presented alongside.
  - Restoring font state with `q`/`Q` **is tracked** (a font stack). It was not in the decision's wording above, so the implementer proposed tracking instead of skipping and the maintainer confirmed it (2026-09-23; the alternative was "skip a font whose Tf changes inside q/Q").
- **Reproduction record** (2026-09-23): with the code before #51, a simple TrueType subset font went from 3884 → 6 glyphs, and the copied `cmap` pointed at old GIDs 43/72/79/82, so all five characters of "Hello" lost their outlines (text extraction unchanged). Reverting to master's renumbering `subset_font` also turns two CID tests (`Identity`, a `/CIDToGIDMap` stream) red — the CID path was reproduced by running it too.
- `extract_page_text_string`, the criterion the compress tests judge by, looks only at ToUnicode, so it cannot catch glyph errors. The tests that look at glyphs find each character through the font's `cmap` (simple) or GID (CID) and compare its outline with the original — the judge is ttf-parser, independent of the subsetting code.
  - The `cmap` and `post` tests check every (subtable, code) of the original and the name of every GID against the subset with ttf-parser. `subset_cmap` also **reads** format 4 with ttf-parser, so that read shares a model with the judge (format 12 is read from raw bytes, and the writing side is fully independent). So on 2026-09-29 the subset output was read separately once with fontTools 4.62: all four subtables reach only the 8 kept glyphs (`.notdef`, H·e·l·o, and hyphen·sterling·ordfeminine·uni00AD kept through the code = GID union), and the kept glyphs' names are the same as in the original.
  - Trap: the glyph names of "Hello" are all standard Macintosh names (<258), so getting the numbering of `post`'s new name list wrong does not show — the name test also keeps Amacron (267) and eng (331), which have custom names, and first checks that at least 2 such glyphs remain.
  - Trap: ttf-parser returns a code that goes to glyph 0 as `None` in format 0 and as `Some(GlyphId(0))` in format 6.
- **Fixture** `justpdf-core/tests/fixtures/NotoSans-Regular.ttf`: taken without modification from `fonts/NotoSans/unhinted/ttf/NotoSans-Regular.ttf` at notofonts/notofonts.github.io commit `28b15b4b43b7bed62b5cf6e6b0b5ff5846270535` (431,364 B, sha256 `f3961a9cde016d41a4879aecda1474d3a36d6bf54fa0e4643de029cc2248b0e8`, pinned by `test_truetype_fixture_is_pinned`). The license, `fonts/LICENSE` (SIL OFL 1.1) from the same commit, is bundled as `LICENSE-NotoSans`. It has `glyf` outlines, so `subset_font` accepts it.
  - **Maintainer decision (2026-09-23)**: the unmodified original (431KB) was chosen. Alternatives considered were a pre-subset keeping only ASCII made with fonttools (tens of KB; a modified copy, so the reproduction steps would need recording) and DejaVu Sans (~750KB, not OFL). Facts presented as grounds: all the existing fixtures together are 36KB, and `justpdf-core/Cargo.toml` has no `include`/`exclude`, so this file ships in the crates.io package. This decision did not cover whether it should be in the package itself (Tracked: #66).

## Reference behaviour
2026-09-23, read the source code directly (#51):
- **Ghostscript** `devices/vector/gdevpsft.c` — keeps GIDs when writing TrueType. Fills `loca` up to the original `numGlyphs + 1` entries, with unused glyphs zero-length; a short `loca` when `glyf` is small.
- **MuPDF** `source/fitz/subset-ttf.c` — CID fonts keep GIDs (`new_num_glyphs = orig_num_glyphs`). Simple fonts are renumbered, and one `cmap` subtable ((3,1)→(1,0)→(0,1)→(0,3), or (3,0)→(1,0) if symbolic) and `post` are regenerated. `source/pdf/pdf-subset.c` — glyphs are collected through full font interpretation (`pdf_font_cid_to_gid`), and a content processor walks the pages, annotations and widgets. Simple fonts have `/FirstChar`, `/LastChar` and `/Widths` narrowed to the codes used.
- **ISO 32000-2** 9.6.6.4 (TrueType glyph selection) was not checked against the spec text — one of the reasons the union approach was made not to depend on which path is chosen.

2026-09-29, read the source code directly (#69):
- **MuPDF** `source/fitz/subset-ttf.c` — `subset_name_table` keeps every record (`filter_name_tables` is always 1) and only merges identical strings. `subset_post` reduces only format 2 (only the kept glyphs' names, using the index for a standard Macintosh name) and **drops** `post` for any other format. For CID fonts it neither builds nor copies `cmap` and `post`. `OS/2`, `cvt `, `fpgm` and `prep` are copied.
- **Ghostscript** `devices/vector/gdevpsft.c` — when writing as CID it drops `cmap`, `name`, `OS/2` and unknown tables. If the original has `post`, it is copied unchanged. Run result (gswin64c 10.06.0 `pdfwrite`, the "Hello" input PDF above): output PDF 29,112 B, font program Flate 25,948 B (73,208 B decompressed) — `numGlyphs` 3884 kept, the original `post` 42,975 B and `GSUB` 11,960 B carried unchanged, and `cmap` built anew as (1,0) format 0 and (3,0) format 4 with 4 entries.

2026-09-30, read from the raw source (#117, `ArtifexSoftware/mupdf` master `a7876256`):
- **MuPDF** `source/pdf/pdf-subset.c` — one `font_usage_t` per font file ("We have one of these records for each fontfile", found by `num`/`gen`), holding the list of top-level font dictionaries that use it and heaps of GIDs and CIDs. `font_analysis_Tf` resolves each font dictionary down to its FontFile/FontFile2/FontFile3 and attaches it to that record; after every page is examined, `subset_ttf`/`subset_cff` runs once per record — the same shape as the per-stream subsetting here. It also merges font files held as different objects but with the same `fz_font_digest`, by pointing the FontDescriptor at the first one. It has no "leave whole" guard, because `examine_page` processes the page contents, every annotation and every widget.

## Known holes / open
- Collection of used codes looks only at `Tj`/`'`/`TJ` in page content (XObjects, annotations, inherited `/Resources` and `"` are blocked by the safety guard above keeping the font whole). That many fonts go unsubsetted. Tracked: #68.
- A shared FontFile2 that a non-candidate font also reaches (one drawn only inside a form XObject, or never drawn on a page) is left whole, since that font's glyphs are not collected. Once collection reaches XObjects this case can be subsetted too. Tracked: #68.
- A font program embedded several times as different objects with the same content is subsetted once per copy. MuPDF merges such files by font digest (Reference behaviour above). `dedup_streams` runs after subsetting, so copies cut differently no longer merge (inferred). Tracked: #140.
- A page whose `/Contents` is a reference to an indirect array contributes no codes and does not mark its fonts unsafe, so a font it shares with another page is cut without its glyphs (measured, 2026-09-30). Decided in #138: one compress-local helper reads `/Contents` (indirect array included) for all four compress sites and reports `Incomplete` for anything it cannot read; on `Incomplete` the page's fonts are left whole and its resources and images untouched. Tracked: #138.
- Subsetted fonts get no subset tag (`ABCDEF+`) on `/BaseFont`/`/FontName`, and a CID font keeps its original `/CIDSet` (inferred from code). Checked against ISO 32000-1:2008 (Adobe's free copy via the web archive, pdftotext, 2026-10-07): §9.6.4 says a subset's BaseFont and FontName "shall begin with a tag followed by a plus sign", six uppercase letters, different subsets in one file getting different tags; Table 122 makes `/CIDSet` optional but, when present, "a stream identifying which CIDs are present in the CIDFont file" (bit table, MSB of byte 0 = CID 0). Decided in #141: one deterministic tag per subsetted program on every dictionary that reaches it, and `/CIDSet` rewritten to the kept CIDs (not dropped, since #58 preserves PDF/A). ISO 32000-2 and PDF/A wording not checked. Tracked: #141.
- `subset_font` can grow an already-subset font: the four producer-subset brochure fonts came out 27–47% larger (above). The size check keeps the original, so nothing is lost, but the subsetter adds bytes such fonts did not carry. Measured 2026-10-08 (probe keeping every non-empty glyph, table lengths in → out): `loca` doubles because the output is always long format (e.g. TAMSTW+Calibri 7,750 → 15,500), `hmtx` is rebuilt at the full spec length although the producer's was truncated (3,974 → 9,694), `cmap` subtables re-encode to about twice their size (278 → 586), and 4-byte glyph padding adds a few dozen bytes to `glyf`; these four sum to the whole growth. Since GIDs are kept, the `loca` and `hmtx` cost scales with numGlyphs on every subset. Decided in #278: short `loca` whenever offsets fit, `hmtx` never longer than the input, a subset `cmap` subtable no larger than its input, and a program with no glyph to empty is left unrebuilt. Tracked: #278.
- A subset font copies the original `name` (maintainer decision) and `OS/2`, `cvt `, `fpgm` and `prep` unchanged.
- CID fonts (which find GIDs through `/CIDToGIDMap`) still get reduced `cmap` and `post`. MuPDF and Ghostscript drop both from CID fonts.
- `cmap` formats 2, 8, 10, 13 and 14 are copied from the original unchanged, so entries for dropped glyphs remain. No test runs the paths that fall back to the original when format 4 exceeds the 16-bit length or format 12 exceeds the mapping limit.
- No test runs the symbolic font path (the `(3,0)` subtable, the `0xF000` prefix) — there is no symbolic TrueType fixture. `Identity-V` is not tested either (only `Identity-H`).
- CFF (FontFile3) is not a subsetting target.

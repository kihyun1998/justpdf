# CJK font embedding (writing)

## What it is
The writing side of text beyond WinAnsi. A caller parses a TrueType program into a `FontProgram` and registers it on one document as a `Font` handle (`add_font`, `add_font_with`), then draws with it through `PageBuilder::set_font` and `show_text`. At output the document writes each embedded `Font` as a Type0 font (`Identity-H`, `CIDFontType2`) with a `/CIDToGIDMap` stream, a ToUnicode CMap, `/W` widths and a font descriptor, the program subset to the glyphs drawn. Standard fonts are `Font`s of the standard kind on the same path (`add_standard_font`), encoding through WinAnsi, or through the built-in encoding for Symbol and ZapfDingbats. `cjk.rs` holds the CID system info, the ToUnicode CMap generator and the `/W` array builder the writer uses.

## Governing decisions
No decision record. The design was settled with the maintainer in #173's grilling (2026-10-02): fonts come only from callers (nothing bundled, no system lookup); a per-document `Font` handle encodes inside `show_text`; subsetting happens at build; `/W` comes from `hmtx`; fallbacks are an ordered chain; characters map one-to-one with no shaping (#177), no bidi and no vertical writing; CFF fonts are refused (#176). It replaced #65's options (a)/(b)/(c). [ADR 0006](../../adr/0006-breaking-changes-are-allowed-before-1-0.md) (breaks before 1.0, no compatibility shims) sits adjacent: it postdates the `set_font_name` deprecation below and does not decide the font design.

- **Maintainer decision (2026-10-22, #173)**: `PageBuilder::set_font(&Font, f64)` is the new signature, and the string form is renamed `set_font_name(&str, f64)` and deprecated (re-verified: `#[deprecated]` on `set_font_name` in `writer/page.rs`). Shown: the brief asked for both a `&Font` `set_font` and a deprecated string `set_font`, which Rust cannot overload. Alternatives: keep `set_font(&str)` deprecated and add `select_font(&Font)`; one generic `set_font(impl Into<…>)`, which cannot warn on the string path. This decision did not cover any other name.

## Design model
Status: from #173's grilling and decisions, and from reading the source and the tests.

- **`FontProgram::parse(bytes, face_index)`** holds one standalone TrueType font in shared bytes (`Arc<[u8]>`). A `.ttc` face is rewritten as a standalone font (`collection_face`: its offset table, then each of its tables copied and 4-byte aligned), because `/FontFile2` holds one TrueType font and `subset_font` reads the offset table at byte 0 (inferred). So `FontEmbedding::Whole` for a collection face embeds that face's bytes, not the collection. `OTTO` (at the start or as the face's version) is refused with a `FontError` naming CFF (`a_cff_font_is_refused_naming_the_format`), and so are a program with no `glyf` table and a face index other than 0 on a single font.
  - **Input bound.** The program comes from the caller. A face's table records can all point at the whole file, so copying them is a memory bomb — 65,535 records over a 1 MiB collection would copy about 64 GiB (inferred). The tables of one real face do not overlap, so a face whose tables add up to more than the collection is refused, which bounds the copy by the collection's size (`collection_face`). Measured on #173's review: without the guard, 4,096 records over a 65 KiB file copied 268 MB in 0.21 s; `a_collection_face_whose_tables_repeat_the_whole_file_is_refused` pins the refusal. Nothing else bounds the program's size.
- **A `Font` is a chain of registered entries**, the primary first. `with_fallback` appends the fallback's own chain without duplicates, and panics for a font of another document. Each entry belongs to one document (a process-wide counter in `FontRegistry::new`), has a resource name (`F1`, `F2`, … from `next_resource_name`), object numbers reserved at registration, and its usage behind a `Mutex`, so `PageBuilder` stays `Send` (technical decision: `PageBuilder` encodes on `show_text` without the document, so the handle carries the document's state).
- **Choosing the font for a character**: the first entry that has a glyph for it — an embedded font through its `cmap` (glyph 0 counts as none), a standard font when its encoding has a code for it (WinAnsi; Symbol's or ZapfDingbats' built-in encoding for those two since #336 — until then they answered through WinAnsi and drew other glyphs, `a` as α, measured on #336). A character no entry has goes to the primary: `.notdef` (GID 0) in an embedded font, `?` in a standard one (a space in ZapfDingbats, which has no `?`; technical decision, #336), and it is recorded as missing. `missing_chars()` is the union over the document's entries.
- **Each entry caches its glyph per character** (`FontEntry::glyphs`: glyph ID and advance), because `FontProgram` holds only bytes and every lookup through it re-parses the face with `ttf_parser::Face::parse`. Measured on #335 (release): 144–189 ns a parse against 30–53 ns for `glyph_index` on a parsed face, and choosing and encoding one character looked it up two or three times per entry tried. The cache lives on the per-document entry, not on `FontProgram`, which would share a lock across documents (technical decision, #335). Measured with `benches/text.rs` `show_text_embedded_fallback_100lines` (Hangul fixture + Noto Sans, 9,400 characters): 8.02 ms before, 1.51 ms after; `show_text_helvetica_100lines` 0.54 ms (#335; not rerun 2026-10-30). `FontEntry::write` still looks glyphs up through `FontProgram::glyph_id`, outside the cache (inferred).
- **Usage is recorded when `show_text` runs, not when the page is added**: a `PageBuilder` drawn and then dropped still adds its characters to the CIDs, the subset and `missing_chars()` (measured by #173's review probe). **Maintainer decision (2026-10-22, #173)**: kept and documented (the `Font` doc comment says so). Shown: the probe; alternative: record at `add_page`, which needs the content encoded late.
- **CIDs** are assigned per entry in order of first use from 1, one per distinct character, missing characters included. CID 0 is never assigned; past 65,535 distinct characters a character gets CID 0 and is reported missing (`encode_char`). The `/CIDToGIDMap` stream maps CID 0 to 0 and each CID to its character's glyph (0 when missing), so ToUnicode can give every CID, `.notdef` ones included, its exact character (`two_different_missing_characters_extract_back_distinctly`).
- **`show_text`** splits the text into runs per entry, writes `/Fn size Tf` before a run in another entry than the active one, and the selected font's `Tf` again after the last run if it switched, so the content stream's font after `show_text` is what `set_font` selected whatever `q`/`Q` the caller wraps around it (technical decision). Each run is `(…) Tj`, or `<hex> Tj` when the bytes are not all printable ASCII. Every entry a page draws with is declared in its `/Resources /Font`. After `set_font_name`, or with no font selected, the text is written as WinAnsi codes.
- **What an embedded entry writes** (`FontEntry::write`): Type0 `/Encoding /Identity-H`, `CIDSystemInfo` Adobe/Identity/0, `/DW` the `.notdef` advance and `/W` per CID, both `hmtx` × 1000 / unitsPerEm rounded to integers (measured on a 2048-unit fixture: `A` 1489 → 727). The descriptor's `FontBBox` comes from `head`, `Ascent`/`Descent` from ttf-parser's `ascender`/`descender` — `OS/2` typo metrics when `USE_TYPO_METRICS` is set, `hhea` otherwise (measured: the fixture sets it, 1753/−295 → 856/−144 where `hhea` gives 844/−156) —, `CapHeight` from `OS/2` (the ascent without it), `ItalicAngle` from `post`, `Flags` Nonsymbolic plus FixedPitch and Italic from the tables, `StemV` 80 (`descriptor`; `widths_and_descriptor_metrics_come_from_the_font_tables`).
  - Flags Nonsymbolic for a CID font follows MuPDF (Reference behaviour); ISO 32000-2 §9.8.2's Symbolic meaning was not checked against the spec text.
- **Subsetting at output**: `subset_font` with the GIDs drawn plus 0. It keeps glyph IDs ([Font subsetting](font-subsetting.md)), so the `/CIDToGIDMap` stays valid. The name gets a six-letter tag from `font_hash` of the kept GIDs (`subset_tag`, `ABCDEF+PostScriptName`) in `/BaseFont` of both dictionaries and the descriptor's `/FontName`. If `subset_font` refuses, the whole program is embedded untagged. Measured on #173: Noto Sans for "Hello" embeds 41,236 bytes of 431,364 (decompressed); most of it is `loca` and `hmtx`, full length because GIDs are kept. `the_embedded_program_is_a_tagged_subset_of_the_used_glyphs` bounds it at 45,000.
- **When objects are written**: every entry's numbers are reserved at registration and its objects written at them by `FontRegistry::write` (a standard entry's dictionary, an embedded entry's six objects). `DocumentBuilder::build` calls it, and `DocumentModifier` calls it (`write_fonts`) before `build`, `pack_object_streams`, `build_with_xref_stream` and `incremental_save`. An entry is rewritten only when it drew a new character since its last write, so `build_with_xref_stream` after `pack_object_streams` does not put a second copy beside the packed one (technical decision). Until #173's review a standard entry was written at registration, and a `garbage_collect` before the page using it was inserted removed it, leaving the page's resource pointing at nothing (`a_standard_font_registered_before_garbage_collect_is_still_written`).
- **A page and its fonts belong to one document**: `DocumentBuilder::add_page` asserts that every font a page draws with is the builder's (`FontRegistry::owns`), and `DocumentModifier::insert_page` returns a `FontError` (`a_page_drawn_with_another_documents_font_is_refused`, `a_modifier_refuses_a_page_drawn_with_another_documents_font`).
- **Measuring**: `FontProgram::advance` (thousandths of an em, unrounded) and `Font::advance(text, size)` through the chain; a standard font measures with `standard14_widths` at the code it writes. Measuring records nothing.
- `cjk.rs` `generate_to_unicode_cmap` splits bfchar sections into chunks of 100 (code comment: "PDF spec limit") and writes characters outside the BMP as surrogate pairs. `detect_ordering` and the Adobe orderings have no writing caller: every embedded font is Identity (inferred, `git grep` 2026-10-30).
- `build_cid_font` (whole program, `/CIDToGIDMap /Identity`, every width 1000, constant descriptor metrics, no product caller) was removed in #173; the compress tests that need a whole-program Type0 font build it through `FontRegistry` with `FontEmbedding::Whole`.

Measured: the 20 tests in `tests/unicode_font.rs` and `render_embedded_font.rs` pass at 88b2a08 (2026-10-30).

## Reference behaviour
2026-10-22, read from the raw source (`ArtifexSoftware/mupdf` master, `source/pdf/pdf-font-add.c`, #173):
- **MuPDF** `pdf_add_font_descriptor` — used for its CID fonts too — writes `Flags` `PDF_FD_NONSYMBOLIC`, `ItalicAngle` 0 and `StemV` 80, and `Ascent`/`Descent` from FreeType's face ascender/descender × 1000 / units per em. justpdf writes the `post` italic angle instead of 0, and the same `StemV`.

## Blast radius
- [Document builder](document-builder.md), [Document modifier](document-modifier.md) — they own a `FontRegistry` and must write it before every output; a new output path that skips `write_fonts` writes pages pointing at font objects that were never written.
- [Incremental save](incremental-save.md) — `incremental_save` writes the modifier's fonts; the same rule holds for any new save path.
- [Font subsetting](font-subsetting.md) — `subset_font` also runs at build; a change to whether it keeps glyph IDs breaks the `/CIDToGIDMap` written here.
- [CID fonts](cid-fonts.md), [ToUnicode](tounicode.md), [Glyph rendering](glyph-rendering.md) — the readers of these fonts (text extraction and both renderers); what is written must decode there to the same characters.
- [Font encodings](font-encodings.md) — standard `Font`s encode through `winansi_code`, `symbol_code` and `zapf_dingbats_code`; Symbol and ZapfDingbats text then extracts through StandardEncoding.
- [Form appearance](form-appearance.md), [Signature appearance](signature-appearance.md), [Format document](format-document.md), [OCR](ocr.md) — planned users of `Font` (#175, #174, #322); a change to the handle's contract changes their design.

## Known holes / open
- No shaping, bidi or vertical writing: Arabic, Hebrew, Indic scripts and conjoining Hangul jamo draw wrongly. Tracked: #177.
- CFF-flavoured OpenType fonts are refused. Tracked: #176.
- `FontRegistry::write` is crate-internal and needs a registry; `sign_pdf` writes its incremental update by hand and cannot reach it, so signature, stamp and default form appearances cannot draw with a caller's `Font`. Tracked: #175.
- Text converters draw in Courier with fixed-width wrapping and take no caller font. Tracked: #174.
- The OCR text layer cannot draw non-WinAnsi text through a `Font`. Tracked: #322.
- After an output has written the fonts (`pack_object_streams`), a `garbage_collect` removes a font no page reaches yet, and a later page drawn with it is not given it again unless it draws a new character: the entry counts as written (inferred).
- A page drawing only with by-name fonts (`set_font_name`) is not checked against the document (inferred).
- Open question for the maintainer: ADR 0006 (2026-10-24) says avoiding a break is not a reason to add a compatibility shim. Should the deprecated `set_font_name` (and `embed_truetype_font`) stay, or go under that rule? The #173 decision (2026-10-22) predates the ADR.

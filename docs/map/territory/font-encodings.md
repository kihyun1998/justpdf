# Font encodings (simple fonts)

## What it is
The encoding tables (Standard, WinAnsi, MacRoman, PDFDoc, Identity) that turn a simple font's 1-byte codes into Unicode, and the interpretation of `/Encoding`. It is the path text extraction uses when there is no ToUnicode, and the decoder for PDF text strings (PDFDocEncoding / UTF-16BE BOM) also lives here.

## Governing decisions
**None.**

## Design model
- A simple font's code becomes text in this order: ToUnicode (when it maps the code), else a `/Differences` glyph name, else the base encoding's table (`FontInfo::decode_simple_code`). The base encoding is the `/Encoding` name, or an encoding dictionary's `/BaseEncoding`, else `StandardEncoding` — a symbolic font's built-in encoding from the font program is not read. Text extraction resolves an indirect `/Encoding` (`5 0 R`) before `parse_font_info`, which has no document access; until #221 an indirect one fell back to `StandardEncoding` (measured, `tests/font_encoding.rs`).
- One `/Differences` parser (`parse_differences`) serves general simple fonts and Type3. A code outside 0–255 is skipped, and a run does not wrap past 255.
- A glyph name becomes text by the Adobe Glyph List rules (`glyph_name_to_unicode`): the part before the first `.`, split at `_`, each component looked up in the AGL or read as `uniXXXX…` / `uXXXX`–`uXXXXXX` (upper-case hex only, no surrogates). A name that maps to nothing (`g123`) yields no text, not the code's base-encoding letter. The whole AGL is vendored (`font/agl.rs`, 4,281 names, BSD-3-Clause notice kept) — maintainer's call in #221 (2026-10-07), chosen over only the ~330 names the Annex D encodings use, because `/Differences` in real files also names Cyrillic/Greek/`afii` glyphs; pdf.js and MuPDF carry the whole list too.
- StandardEncoding and MacRomanEncoding each decode through their own Annex D table (`font/encoding_tables.rs`); a code with no glyph in the table yields nothing. Both tables, and the AGL, are generated by `scripts/gen-font-tables.py` from the AGL's `glyphlist.txt` and pdf.js `src/core/encodings.js`; the script runs rustfmt, so regenerating reproduces the committed files. Until #221 both were decoded with the WinAnsi table.
- The WinAnsi table stays hand-written. The script's cross-check against Annex D (measured 2026-10-07): it agrees on every code except 0x7F, 0x81, 0x8D, 0x8F, 0x90, 0x9D (pdf.js: bullet; here: the code as a C1 control), 0xA0 (Annex D glyph `space`; here U+00A0) and 0xAD (`hyphen`; here U+00AD).
- `encode_winansi` is the inverse of the WinAnsi table for the writing side: encode_winansi` (next to the WinAnsi decode table in `font/encoding.rs`): ASCII as it is, any other character its Windows-1252 code, `?` when it has none — including the five codes WinAnsi leaves without a glyph (0x81, 0x8D, 0x8F, 0x90, 0x9D). justpdf's standard fonts are declared `/WinAnsiEncoding` (#34), so their `'` and `` ` `` extract as themselves; a file with no `/Encoding` still decodes through StandardEncoding.
- The renderer does not use these encodings: `char_code_to_glyph_id` treats the byte as a Unicode scalar and looks it up in the font's cmap.
- The function that decodes PDF text strings correctly (`decode_text`, handling the UTF-16BE BOM) is here, but the annotation, outline, form and signature readers do not use it; they use `from_utf8_lossy` — [Text string encoding](../invariant/text-string-encoding.md).

- `justpdf-core/tests/font_encoding.rs` — extraction through `/Encoding` on synthetic pages

## Reference behaviour
- Annex D tables as transcribed by pdf.js (`src/core/encodings.js`), and the Adobe Glyph List — the generator's inputs. The tests check the issue's measurements: `/Differences [65 /B]` `(A)` → `B`, `/MacRomanEncoding` `<8E>` → `é` (before #221: `A`, `Ž`).

## Cross-cutting invariants
- [Content text encoding](../invariant/content-text-encoding.md) — `encode_winansi`, the writing side of the WinAnsi table.
- [Text string encoding](../invariant/text-string-encoding.md) — where the only correct decoder lives.
- [Font resolution](../invariant/font-resolution.md) — text uses these tables, render uses the font's cmap.

## Blast radius
- [Text extraction](text-extraction.md) — `show_string` calls `decode_simple_code` for one-byte codes, `decode_text` for two-byte codes.
- [Glyph rendering](glyph-rendering.md) — the side that does not use the encodings. Supporting `/Differences` means adding it to render separately too (#223).
- [Type3 fonts](type3-fonts.md) — uses `parse_differences`.
- [Font subsetting](font-subsetting.md) — resolves `/Differences` names and base tables on its own, without the AGL and tables here.
- [ToUnicode](tounicode.md) — the higher-priority mapping.

## Known holes / open
- A symbolic simple font without ToUnicode decodes through StandardEncoding, not its built-in encoding.

# Content interpreter

## What it is
The graphics- and text-state interpreter in `justpdf-core` (`content/interpret.rs`). `interpret` walks a parsed content stream and reports to a `ContentVisitor`: each operation with the state in effect before it runs, and each shown glyph (`Glyph`) with its code, CID, bytes, the operation and `TJ` element it came from, its width, its text rendering matrix, its box and whether it is in hidden optional content. Resource names resolve through `ContentResources`: `DocResources` reads a document, the test-only `MapResources` reads in-memory maps. [Text extraction](text-extraction.md) is its one production caller; [Redaction](redaction.md) and sanitizing are decided to run on it and do not yet. Everything is `pub(crate)`; the public API sees only `text::Matrix`, a re-export.

## Governing decisions
- [ADR 0004 — Redaction never under-erases](../../adr/0004-redaction-never-under-erases.md), "One interpreter for extraction and redaction": glyph positions for redaction come from this interpreter, so a glyph extraction reports inside an area is one redaction erases, and `justpdf-render`'s walkers are out of reach because render depends on core. The glyph box rule (advance width by the `/FontBBox` height, −0.25…1.0 × size without one, through the text rendering matrix and the CTM) is the ADR's.
- [ADR 0005 — Sanitizing removes unpainted text by category](../../adr/0005-sanitizing-removes-unpainted-text-by-category.md), "Unseen content": each glyph, path and image sanitize removes is decided through the interpreter redaction uses, and hidden optional content is judged by the default configuration, as text extraction judges it. Not built (no sanitize code at 88b2a08); paths and images are not interpreted here yet.

## Design model
From the two ADRs for the glyph box and the one-interpreter rule; the rest from reading the source and its unit tests (`content/interpret.rs` `mod tests`).
- **State**: `q`/`Q`, `cm`, `Tm`/`Tlm`, and the text state `Tc`, `Tw`, `Tz`, `TL`, `Tf`, `Ts`, `Tr` (ISO 32000-2 §8.4, §9.3). `Tm` and `Tlm` are not part of the saved state, as the standard says. `T*`, `'` and `"` move down by the current `TL`; `TD` sets `TL` to −ty; `"` sets `Tw` and `Tc` first.
- **Glyph displacement** follows §9.4.4 as text extraction computed it before the move (#207), and extraction output did not change: *measured* 2026-10-08, `justpdf text --format json` on the repository's 30 PDFs and 11 local PDFs (about 80 MB of JSON) byte-identical before and after (#207). A behaviour kept on purpose by that move: `Tw` is added for any code 32, two-byte codes included, where the standard limits it to a single-byte code 32 (`show_string`). Tracked: #314.
- **Widths and the glyph box** are in 1/1000 text space units for every font: `w0 / 1000`, and `/FontBBox` divided by 1000 (`show_string`, `ResolvedFont::glyph_height`). A Type3 font's `/FontMatrix` is not applied (#312). The box spans the advance width (the font's width, without `Tc` or `Tw`) and the `/FontBBox` height, through the text rendering matrix, so `Tz`, `Ts`, `Tm` and the CTM all apply. A `/FontBBox` given by its other two corners is normalised (§7.9.5 allows any two opposite corners); one with no height (`[0 0 0 0]` is common) counts as absent and the default height is used, because a zero-height box would erase nothing (ADR 0004: when unsure, erase). The box uses the font's own descriptor, or a Type0's descendant's. A glyph shown with no resolvable font gets width 500 and the default height.
- **Codes**: a Type0 font's codes are split and mapped to CIDs by its encoding CMap ([CID fonts](cid-fonts.md), #303), and widths are looked up by CID; `Glyph::code` stays the code (for ToUnicode) and `Glyph::cid` carries the CID. A predefined CMap other than Identity is read as Identity-H (#306). Any other font reads one byte per code, or two for a simple font whose encoding is `Identity` (`ResolvedFont::is_two_byte`). Advance is always horizontal: vertical writing mode is not read (#313).
- **Fonts**: `load_font` replaces indirect `/Widths`, `/FirstChar`, `/LastChar`, `/Encoding`, `/W`, `/DW` and `/FontDescriptor` by their values through `font::resolve_font_entries`, for the font and for a Type0's descendant, so an indirect descriptor is filled in (before #207 it read as absent). A font is resolved **when `Tf` runs** and the text state holds the resolved font, not its name — [Resource name scope](../invariant/resource-scope.md). Each scope chain remembers what a name resolved to; fonts reached by reference are cached by reference across the page and its forms (`DocResources::font_by_ref`, shared `Rc`).
- **`gs`** applies only the ExtGState's `/Font` entry (#235): a direct two-element array of an indirect font reference and a number sets font and size as `Tf` would, with an empty font name; the font is looked up by reference, sharing the cache, so it need not appear in any `/Font` dictionary. Any other shape changes nothing — the rule the raster and SVG renderers follow too (#238), as [Font resolution](../invariant/font-resolution.md) asks. Pinned by `tests/extgstate_font.rs`. Other ExtGState keys are ignored.
- **Form XObjects** are entered only with `InterpretOptions::enter_forms`, which only the unit tests set; text extraction passes the default (#48). Entering applies `/Matrix`, pushes the form's `/Resources` in front of the caller's (a form without one uses the caller's), saves the graphics state, the text matrices and the marked-content state, and restores them on leaving. Inside a form `Q` cannot pop below the depth at entry (`stack_floor`). A form already being interpreted is refused as `FormRefusal::Cycle`; one that would be the eleventh nested form as `FormRefusal::Depth` (`MAX_FORM_DEPTH` = 10; the raster renderer's guard `xobject_depth > 10` lets eleven levels in) — [Content stream recursion](../invariant/content-stream-recursion.md). `/BBox` clipping is not tracked.
- **Optional content is flagged, never skipped** (#219). A glyph is `hidden` inside an `/OC` marked-content section whose `/Properties` name is hidden, or in a form whose `/OC` is hidden (`FormXObject::hidden`) or that is drawn inside hidden content. `DocResources::properties_hidden` looks the name up innermost scope first and evaluates it with `ocg::is_oc_visible` under the default configuration, read once per page and shared with form scopes. Nesting is counted over `BMC` and `BDC`; the outermost hidden section governs and only its own `EMC` ends it (ISO 32000-1 §8.11.3.2 NOTE 2, read raw for #219). Every operator still runs — [Hidden content keeps its state](../invariant/hidden-content-state.md). A form starts with no section open and its caller's state is restored on leaving. A property list given inline (`/OC <<…>> BDC`) is treated as visible, since §8.11.3.2 asks for a named resource (`process_op` reads only a name operand); the renderers evaluate an inline one (below).
- **Not interpreted**: marked content other than `/OC`, clipping, colour, paths, images, shadings and inline images.
- **Bounds on input**: the operation list is the parser's ([Content stream parsing](content-stream-parsing.md)); `q` pushes are bounded only by the number of operations. With forms entered, nesting is capped at 10 but the number of `Do`s per level is not, and each `Do` decodes and parses the form again (`DocResources::form`), so a form drawing the next one k times costs about k^10 runs — the explosion [Content stream recursion](../invariant/content-stream-recursion.md) records for the renderer (inferred; no production caller enters forms today).

## Blast radius
- [Text extraction](text-extraction.md) — takes each glyph's origin, size and width from here; a change in position or width changes word grouping and so [Reading order](reading-order.md), [Text output formats](text-output-formats.md) and [Text search](text-search.md).
- [Redaction](redaction.md) — ADR 0004 makes this interpreter's glyph boxes the erase test; a box made narrower here under-erases once redaction runs on it (#209).
- [Optional content](optional-content.md) — `is_oc_visible` decides `hidden`; the renderers decide the same content through `optional_content::section_visible`, and the two now disagree on inline property lists.
- [Content stream parsing](content-stream-parsing.md) — reads operands by shape; a token parsed as another `Operand` variant is ignored here.
- [Font loading](font-loading.md), [CID fonts](cid-fonts.md), [ToUnicode](tounicode.md), [Type3 fonts](type3-fonts.md) — `load_font`'s input; a width table or CMap read differently moves every glyph after it.
- [Render interpreter](render-interpreter.md), [SVG renderer](svg-renderer.md) — separate operator walkers in `justpdf-render` keeping the same text-state rules; a positioning fix on one side has to decide whether the others need it.

## Known holes / open
- Text inside Form XObjects is not extracted, because extraction does not set `enter_forms`. Tracked: #48.
- `Tw` is added to two-byte code 32. Tracked: #314.
- Type3 widths and `/FontBBox` skip `/FontMatrix`, so boxes can be 10× too narrow. Tracked: #312.
- Vertical writing advances horizontally. Tracked: #313.
- A predefined CMap other than Identity is read as Identity-H. Tracked: #306.
- An inline `/OC` property list is visible here and evaluated by the renderers, so a page can draw nothing where extraction reports text (measured 2026-10-30, probe: `/OC << /Type /OCMD /OCGs [5 0 R] >> BDC (InlineHidden) Tj EMC` with group 5 OFF in `/D` extracts `InlineHidden`; the renderer side read from `optional_content::section_visible`, not run). Which side moves is open: the core reading follows §8.11.3.2, ADR 0005 asks that extraction and sanitizing judge alike.
- Once forms are entered, work per page is bounded only by nesting depth (above, inferred).

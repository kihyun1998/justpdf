# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Added
- **Text beyond WinAnsi (Korean, Japanese, Chinese, Cyrillic, …) through a caller-supplied TrueType font** — `font::FontProgram::parse(bytes, face_index)` reads a `.ttf` or one face of a `.ttc` (a CFF-flavoured `OTTO` font is refused with `JustPdfError::FontError`, new). `DocumentBuilder::add_font` and `DocumentModifier::add_font` register it on a document as a `font::Font`, and `PageBuilder::set_font(&font, size)` selects it and declares it in the page's `/Resources`, so a page can now draw with an embedded font through the public API (#65). `show_text` writes 2-byte CIDs for it. `Font::with_fallback` chains fonts: each character goes to the first font that has a glyph for it, the runs separated by `Tf` at the same size. A character no font has is drawn as `.notdef` and reported by `missing_chars()` (new, on both builders); drawing never fails. Characters map one-to-one through the `cmap`: no shaping, no bidi, no vertical writing. Each font is written as a Type0 font (`Identity-H`, `CIDFontType2`): CIDs in order of first use with a `/CIDToGIDMap` stream, a ToUnicode entry for every CID (surrogate pairs outside the BMP), `/W` and `/DW` from `hmtx`, descriptor metrics from `head`, `hhea`, `OS/2` and `post`, and the program subset to the glyphs drawn under a six-letter subset tag. `add_font_with(&program, FontEmbedding::Whole)` embeds the whole program untagged instead. `Font::advance` measures a string through the chain. The facade re-exports `Font`, `FontProgram` and `FontEmbedding` as `justpdf::Font` etc. (#173)
- **Brand assets** — the justpdf logo under `logo/`, shown at the top of every README and as the docs.rs logo and favicon
- `writer::embed_rgb` (also `justpdf::embed_rgb`) — embed 8-bit RGB pixels as a Flate-compressed image XObject, for `PageBuilder::add_image` / `draw_image` (#88)
- **CLI `compress` subcommand** — `justpdf compress <file> --preset low|medium|high|extreme -o <out>` (#10)
- **CLI `compress` options** — per-knob overrides on top of `--preset` (`--jpeg-quality`, `--max-dpi`, `--no-strip-metadata`, …) (#11), `--password` for encrypted input (output is unencrypted) (#13), `--analyze` preview (#12), `--verbose` breakdown (#14)
- **Release workflow** — pushing a `v*` tag builds CLI binaries for Linux, macOS (x86_64, aarch64) and Windows and attaches them to the GitHub release (#15)
- `crypto::random_file_id` — a random 16-byte file identifier for a newly written file (#31)
- `DocumentModifier::set_encryption` — `build` then writes the document encrypted, keeping `/Info`; the trailer `/ID` keeps the source's first element and gets a new second element (#75)
- `ContentOp` is now `PartialEq` (#29)
- `DocumentModifier::preserve_encryption` (also `justpdf::Modifier::preserve_encryption`) — `build` writes an encrypted source document encrypted as it was, with its `/Encrypt` dictionary and file key, so both of its passwords open the output although only one was used to open it; the trailer `/ID` keeps the source's first element. Of `preserve_encryption` and `set_encryption`, the later call wins; `build_with_xref_stream` refuses it for an encrypted source, and `incremental_save` accepts it (#102)
- `DocumentModifier::pack_object_streams` — pack eligible objects into object streams for `build_with_xref_stream`, leaving objects at a generation other than 0 unpacked and numbering each object stream above every number the source uses, as ISO 32000-1 §7.5.7 requires (#106)
- `Document::from_bytes_with_password`, `open_with_password` and `open_mmap_with_password` (`mmap` feature) — open an encrypted document with its user or owner password (#99)

### Changed
- **Text extraction leaves out text in optional content hidden under the default configuration** — `extract_page_text`, `extract_all_text`, their `_string` forms, and so CLI `text`, the facade's `Page::text` and the bindings, no longer return text in a layer that is OFF in `/OCProperties /D` (an `/OC` marked-content section whose `/Properties` group or OCMD is hidden, nested sections included). Hidden text still advances the text position, so what follows it stays where it was. `text::TextExtractOptions { include_hidden: true }` with `extract_page_text_with_options` or `extract_all_text_with_options` (new) gives the previous output (#219)
- **`ocg::OCMembership` gains `expression: Option<VisibilityExpression>` (new)**, `parse_ocmd` accepts an OCMD without `/OCGs`, and `ocg::is_oc_visible(oc, doc, config)` (new) decides any `/OC` value (#44)
- **`justpdf_core::function::PdfFunction` gains `Array`**, and `justpdf_render::shading`'s `parse_gouraud_triangles`, `parse_lattice_vertices` and `parse_patch_mesh` take a components-to-RGBA closure instead of a colour space, and `rasterize_triangle` an optional function table (#233)
- **`justpdf_core::function::PdfFunction` gains `Sampled` and `PdfFunction::resolve(obj, doc)` (new)**, which follows references and decodes stream data; `justpdf_render::shading::render_shading` takes the shading's function, read that way (#47)
- **`justpdf_render::shading::render_shading` takes the shading's resolved `&ColorSpace`**, and its mesh parsers (`parse_gouraud_triangles`, `parse_lattice_vertices`, `parse_patch_mesh`) take `&ColorSpace` instead of a colour space name; `color::ColorSpace::initial_color` (new) (#231)
- **`justpdf_render::device::PixmapDevice::fill_path_with_pattern` and `stroke_path_with_pattern` take an `alpha: f32`**, the opacity the pattern is painted with, before `blend_mode` (#391)
- **`image::DecodedImage` carries `color_space: ColorSpace` and `decode: Option<Vec<f64>>`, and `DecodedImage::to_rgb8` (new) is the one sample-to-RGB conversion**; `is_gray` (new). `color::ColorSpace::resolve(obj, doc)` (new) reads a colour space through references; `ColorSpace::Separation`/`DeviceN` gain `tint: Option<Box<PdfFunction>>`, `ICCBased` gains `alternate`, and `ColorSpace::substitute` (new) gives the space an ICCBased colour converts through without its profile (#46)
- **`justpdf_render::device::PixmapDevice` holds no clip; each drawing method takes `clip: Option<&Mask>`** — `set_clip_path`, `intersect_clip_path` and `clear_clip` are removed, and `clip_mask(path, rule, transform)` (new) builds a mask for a path. `graphics_state::GraphicsState::has_clip` is replaced by `clip: Option<SharedMask>` (new type, a shared `Mask`), and `SoftMask::mask` is a `SharedMask` (#50)
- **`form::parse_acroform` gives one `FormField` per terminal field, with its widgets in `FormField::widgets` (new)** — a field's kids without `/T` are its widget annotations, so a radio group is one field with the group's `/V`, where each widget was a separate field with the group's name and no value. Code that builds a `FormField` with a struct literal needs the new field (#204)
- **`form::appearance::generate_field_appearance` returns `Result<IndirectRef, AppearanceError>`** instead of `Option<IndirectRef>`: `NoRect` and `Signature` where it returned `None`, and `NotEncodable` (new) when the `/DA` font cannot show the field's text; nothing is added to the modifier then (#178)
- **`DocumentBuilder::add_standard_font` returns a `font::Font`** instead of the resource name, and **`PageBuilder::set_font` takes `&Font`** — `let f = doc.add_standard_font("Helvetica"); page.set_font(&f, 12.0);` with no `add_font` call, since `set_font` declares the font. `Font::resource_name` gives the old name. Its unencodable characters (`?`) are reported by `missing_chars()`. `DocumentModifier::add_standard_font` is new. `font::cjk::build_cid_font` is removed; the Type0 fonts `add_font` writes replace it (#173)
- **`JustPdfError` has a new variant, `FontError { detail }`** — `FontProgram::parse` returns it, and `DocumentModifier::insert_page` for a page drawn with another document's `Font`; a `match` over `JustPdfError` without a wildcard arm needs a new arm (#173)
- **`justpdf_core::font::resolve_font_entries` also resolves an indirect `/FontDescriptor`**, so `parse_font_info` on its result fills `FontInfo::descriptor` (and its `/FontBBox`) where it was `None` for the usual indirect descriptor. Text extraction now runs on a shared crate-internal content interpreter, with unchanged output (#207)
- **`justpdf_core::image::decode_image` takes the document and applies the whole filter chain** — `decode_image(raw_data, dict, doc: &PdfDocument)`. It ran only the last filter's codec on the raw bytes, so a `[/FlateDecode /DCTDecode]` image did not decode and compression skipped it; it now runs every filter in order before the codec, and reads `/JBIG2Globals` from the JBIG2 filter's `/DecodeParms` (an entry that does not resolve to a stream is an error). Pass the raw stream bytes, not `decode_stream` output. `image::extract_jpeg_bytes` likewise applies the filters before `DCTDecode`, where it returned a `[/FlateDecode /DCTDecode]` stream's compressed bytes as the JPEG (#229)
- **The renderers draw Flate-compressed images and apply Flate SMasks and `/Mask`s** — the raster and SVG renderers decoded image streams before `decode_image` decoded them again, so a Flate image drew nothing (no `<image>` in SVG) and a Flate soft or explicit mask was dropped (#229)
- New: `justpdf_core::font::encoding_glyph_name` (a simple font's code → glyph name through `/Differences` and a named base encoding) and `justpdf_render::glyph::GlyphSource` (glyphs from an sfnt, a bare CFF or a Type1 program, addressed by `GlyphRef`) (#224, #225)
- **The renderer picks simple TrueType glyphs through the font's `/Encoding` (ISO 32000-2 §9.6.6.4)** — it read each code as a Unicode scalar, so `/Differences`, MacRoman and the (1,0)/(3,0)/`post` paths were ignored: `/Differences [65 /B]` drew `A`. New: `justpdf_core::font::truetype_glyph_candidates` (candidate glyph IDs in priority order, the renderer drawing the first and font subsetting keeping all), and `justpdf_core::ttf_parser` (a re-export); `justpdf-render` no longer depends on `ttf-parser` itself. Removed: `justpdf_render::glyph::char_code_to_glyph_id`. Font subsetting no longer keeps a font whole for a non-WinAnsi code at or above 0x80, a `/Differences` name only the Adobe Glyph List knows, or any name in a symbolic font (#223, #118, #269)
- **Text justpdf draws in a font it chose is encoded as WinAnsi, and its standard fonts are declared `/WinAnsiEncoding`** — `PageBuilder::show_text`, and so every text converter and the OCR text layer, the signature appearance, the form-field appearance where justpdf picks the font (a text field without `/DA`, combo boxes, list boxes, push buttons) and the stamp appearance wrote the UTF-8 bytes of the text, so `é`, `€` and `—` came out as other glyphs. They now write each character's Windows-1252 code, and `?` for a character WinAnsi cannot hold (`café 한글` → `café ??`). `add_standard_font` and `PageBuilder::add_font` declare `/Encoding /WinAnsiEncoding` (not for `Symbol` and `ZapfDingbats`), and the form and stamp appearances declare the Helvetica they select in their own `/Resources`. New: `font::encode_winansi` (#34)
- **`justpdf_core::font::FontInfo` has a new field, `differences: Vec<(u8, Vec<u8>)>`** — the encoding dictionary's `/Differences`; code that builds a `FontInfo` with a struct literal needs it. New: `FontInfo::decode_simple_code`, `font::parse_differences`, `font::glyph_name_to_unicode` (#221)
- **`justpdf_render::compute_page_transform` turns 90° and 270° pages clockwise** — its 90 and 270 matrices reflected the page across a diagonal instead of rotating it. `render_page`, `render_page_to_pixmap`, `render_page_to_svg` and the parallel variants now also size a `/Rotate 90` or `270` page after rotation (a 600×200 page renders 200×600), where they used the unrotated box and cut content off. (#54)
- **`justpdf_render::glyph_cache::GlyphCache::get_or_insert` takes the font program's hash, not its bytes** — `get_or_insert(font_hash: u64, glyph_id, build_fn)`; compute the hash once per font program with the new `glyph_cache::font_hash` (#163)
- **`justpdf_render::graphics_state` holds the selected font and pattern, not their names** — `TextState::font_name: Vec<u8>` is now `font: Option<FontKey>`, and `GraphicsState::fill_pattern_name`/`stroke_pattern_name: Option<Vec<u8>>` are now `fill_pattern`/`stroke_pattern: Option<PatternSelection>`. `Tf` and `scn`/`SCN` resolve the name when they run, so a Form XObject or pattern tile that inherits the font or pattern keeps the object its caller chose instead of whatever the same name means in its own `/Resources` (#127)
- **`JustPdfError` has a new variant, `LimitExceeded { obj_num, gen_num }`** — a tree walk that revisits shared nodes past its budget fails with it; a `match` over `JustPdfError` without a wildcard arm needs a new arm (#120)
- **`JustPdfError` has a new variant, `PageOutOfRange { index, count }`** — `page::get_page` returns it, where it returned `InvalidObject`, for an index at or past the page tree's `/Count`, or past the last page when the tree has no `/Count`; an index below a `/Count` that overstates the tree is still `InvalidObject`; a `match` over `JustPdfError` without a wildcard arm needs a new arm (#134)
- **`justpdf-render` reports a page index out of range as `RenderError::Core(JustPdfError::PageOutOfRange { .. })`** — `render_page`, `render_page_to_pixmap`, `render_page_to_svg` and `render_pages_parallel` returned `RenderError::InvalidDimensions` for it (#134)
- **Subsetted fonts are much smaller** — `subset_font` (and so `compress_pdf` with `font_subsetting`) copied the font's `cmap` and `post` tables whole, which made up most of a subset: Noto Sans subsetted for "Hello" was 29,201 bytes Flate-compressed. `cmap` now keeps every subtable but only the entries that reach kept glyphs, and a format 2 `post` keeps only the kept glyphs' names; glyph IDs are unchanged. The same subset is now 1,822 bytes. `cmap` formats other than 0, 4, 6 and 12, other `post` formats, and `name` are still copied as they are (#69)
- **`DocumentModifier::catalog_ref` returns the reference by value** (`IndirectRef` instead of `&IndirectRef`), at the generation `build` writes the catalog at — the trailer's `/Root`. Before, it returned the reference read from the source, whose generation differed from the written one once the catalog was set again at a number the modifier no longer held (#112)
- `justpdf-special`: `justpdf-render` is now optional and only pulled in by the `ocr` feature (#1)
- `justpdf-formats`: `justpdf-render` is now optional and only pulled in by the `plaintext`, `mobi` and `fb2` features (#2)
- **`incremental_save` appends only what changed** — it takes the source document instead of its bytes (`incremental_save(&doc, modifier)`, where `doc` is the document the modifier was created from). It appends only the objects whose value differs from the document's and the new ones, marks the objects the modifier removed as free (`65535 f`), and returns the original bytes unchanged when nothing changed; before, every object was appended again (#25)
- **Removed `justpdf_core::crypto::generate_file_id`** — it hashed a title and a timestamp, so the same arguments gave the same `/ID`, and nothing called it. Use `random_file_id` for a new file ID (#76)

### Deprecated
- `PageBuilder::set_font_name(&str, f64)` (the old string `set_font`, renamed), `PageBuilder::add_font(&str, &str)` and `DocumentBuilder::embed_truetype_font` — use a `Font` from `add_standard_font` or `add_font`, selected with `set_font`. Their behaviour is unchanged (#173)

### Fixed
- **A tiling pattern with `/XStep` or `/YStep` below 1 painted the fill colour** — any finite positive step now tiles, since the steps are in pattern space and `/Matrix` scales them (#402)
- **A tiling pattern's `/BBox` was ignored** — the cell is now its bounding box, clipped to it and repeated every `/XStep` and `/YStep`: content left of or below the pattern origin is drawn, a box larger than the step overlaps its neighbours, and content outside a smaller box is cut off (#399)
- **A `cm` before a pattern fill or stroke moved and scaled the pattern** — tiling and shading patterns are now placed in the default space of the content stream they are painted in (the page's, or the form's matrix and the CTM at `Do`), as ISO 32000 §8.7.3.1 requires, so a transformation inside the stream no longer moves them (#397)
- **Tiling patterns were drawn at the wrong size at any resolution but 72 dpi, and ignored the translation and scale of `/Matrix`** — a tiling pattern's cell now lands in pattern space at every resolution (it went through the page transform twice, so cells doubled at 144 dpi) and `/Matrix` moves and scales the tiling instead of the cell's content (#396)
- **Shading-pattern fills and strokes were drawn through the page transform twice, and clipped shadings were slow** — a shading pattern now lands where `sh` would draw the same shading (it came out flipped at 72 dpi and stretched at other resolutions), and `sh` and shading-pattern paints shade only the pixels the paint and its clip can reach: 50 shadings in 100 pt clips on a page at 300 dpi went from about 6.9 s to 0.4 s (#394)
- **`sh` and shading-pattern fills and strokes ignored the alpha constant, and `sh` the blend mode** — a shading painted by `sh` now takes the current `ca` and blend mode, composited once as one object (overlapping mesh triangles included) through the clip and soft mask, and a shading pattern takes `ca` when filled and `CA` when stroked, as a plain fill or stroke does (ISO 32000-2 §8.7.4.2). Tiling patterns are unchanged (#391)
- **Mesh shadings (types 4–7) painted outside the clip and ignored the soft mask** — their triangles now paint through the clip and soft mask like every other draw, blending where the mask is partial, and a pixel on an edge two triangles share is painted once (#383)
- **Axial and radial shadings painted beyond their ends regardless of `/Extend`** — an axial shading now paints only between the lines through its ends, and past an end it extends; a radial shading without `Extend[1]` paints only the region swept between its start and end circles (ISO 32000-2 §8.7.4.5.3–4) (#384)
- **State changes inside hidden optional content were lost in rendering** — the raster and SVG renderers skipped every operator in a hidden `/OC` section, so a `cm`, colour, clip or `q` set there, and the text position after hidden text, did not carry past its `EMC`. Hidden sections now draw nothing (painting operators end the path, text advances unpainted, `Do`, inline images and shadings are skipped) and run every other operator, as ISO 32000-1 §8.11.3.1 requires
- **The SVG renderer emitted optional content OFF in the default configuration** — `render_page_to_svg` now hides what `render_page_to_pixmap` hides: `/OC` marked-content sections whose group or OCMD is hidden (names looked up in the current `/Properties`, nested marked content counted) and Form and image XObjects whose `/OC` is hidden (#218)
- **Optional content (layers) OFF in the default configuration was drawn** — the renderer now looks `/OC /Name BDC` names up in the current `/Properties` resources and hides OFF sections, Form and image XObjects and annotations whose `/OC` is OFF, and evaluates OCMD `/VE` visibility expressions (#44)
- **Axial, radial and mesh shadings ignored most of `/Function`, and free-form meshes drew nothing** — every shading type now evaluates its function through `PdfFunction` (arrays of 1-out functions included): axial and radial shadings sample it across `/Domain`, and meshes with a function interpolate one parametric value per vertex before applying it. Free-form (type 4) meshes follow the edge-flag rules, so a triangle whose vertices are all flagged 0 is drawn (#233)
- **Sampled (Type 0) and filtered PostScript (Type 4) functions were not read, and some malformed functions panicked** — `PdfFunction::resolve` reads a document's function through references and stream filters, sampled functions interpolate multilinearly per ISO 32000 §7.10.2, and evaluation never panics on short `/Domain`s, reversed bounds or truncated sample tables. Tint transforms, soft-mask `/TR` and function-based shadings use it, so spot colours and such shadings paint their colours instead of gray (#47)
- **Fill and stroke colours and shadings in resource colour spaces painted the wrong colours** — `cs`/`CS` in the raster and SVG renderers look a name up in the current `/Resources /ColorSpace` (forms and patterns included), resolve it, and set its initial colour; `sc`/`scn` components and shading output convert through the core colour model, so Indexed, Separation, DeviceN and ICCBased colours paint as given, and the SVG renderer no longer fills a `/DeviceRGB` resource black (#231)
- **Images in Indexed, ICCBased, Separation and DeviceN colour spaces, at 1, 2, 4 or 16 bits per component, or with `/Decode`, rendered and compressed in the wrong colours** — `decode_image` resolves the image's colour space through the document, and the raster renderer, the SVG renderer and `compress_pdf` convert samples through `DecodedImage::to_rgb8`, which unpacks every bit depth with row padding, applies `/Decode` and converts through the palette, tint transform or ICCBased `/N` and `/Alternate`. `compress_pdf` no longer panics on a 16-bit image, and recompresses Indexed images in their colours (#46)
- **Soft masks ignored `/BC` and `/TR`** — `justpdf-render` now composites a Luminosity soft mask's group over its `/BC` backdrop (in the group's colour space, black by default) and passes the mask values through `/TR` (ISO 32000 Table 144). A `/TR` function that does not parse acts as `Identity` (#374)
- **State leaked across nested content streams, and mask and group forms inherited alpha, blend and soft mask** — `justpdf-render` now runs every Form XObject, transparency group, soft mask `/G` and pattern tile on a floored copy of the graphics state: an unmatched `q` or `Q` inside one stays inside, the caller's state is restored even when the content fails part-way, and the caller's current path does not reach a tile. A soft mask form and a transparency group's content start from blend Normal, alpha 1 and no soft mask, and the group is composited once with the alpha, blend mode and soft mask current at `Do` (ISO 32000 §11.6.6). The SVG renderer floors its form path the same way (#128)
- **The soft mask was ignored by pattern fills and strokes, `sh`, text and stencil masks, and by indirect `/SMask` and `/Group`** — `justpdf-render` now masks every painting path with the current soft mask, reads an ExtGState's `/SMask` and a form's `/Group` through an indirect reference, and draws an image XObject that has its own `/SMask` or `/Mask` without the graphics state's soft mask, as ISO 32000 §11.6.4.3 gives (#129)
- **`Q` did not restore a nested clip, and a soft mask leaked into the clip** — `justpdf-render` now keeps the clipping path in the graphics state (ISO 32000 §8.5.4), shared on `q` and restored on `Q`. The soft mask is applied per draw and no longer merged into the clip, so it ends with its `Q` or `/SMask /None`, and each draw under it is masked once instead of compounding (#50)
- **A Form XObject painted outside its `/BBox`** — `justpdf-render` now clips every form drawn by `Do` to its `/BBox` through its `/Matrix` and the CTM (ISO 32000 §8.10.1), transparency groups and nested forms included, and restores the clip after it. Annotation appearances were already clipped (#206) (#365)
- **`form::flatten_form` drew appearances at the wrong size through an undefined XObject name, skipped checkboxes and left widgets behind** — it now draws each widget's normal appearance (its `/AS` state for a checkbox) by ISO 32000-2 §12.5.5, names it in the page's `/Resources /XObject`, wraps the existing content in `q … Q`, removes every widget (Hidden and NoView ones without drawing them), and reads from the modifier so values filled before flattening are the ones drawn. The §12.5.5 placement is new public API in `annot::placement` and is shared with the renderer (#40)
- **The renderer drew no compressed annotation appearance, and drew others at the wrong place** — `justpdf-render` now decodes the `/AP /N` stream, picks the `/AS` entry of a state dictionary, maps the appearance's `/BBox` (through its `/Matrix`) onto the annotation's `/Rect` as ISO 32000-2 §12.5.5 gives, and clips it to `/BBox`. Filled form fields and annotations written by `justpdf-core` now show in rendered pages (#206)
- **A `/Rect` or page box written upper-right corner first was anchored at the wrong corner** — `page::Rect::from_pdf_array` now normalises the two corners (`llx ≤ urx`, `lly ≤ ury`), as MuPDF and pdf.js do; `Rect::normalized` is new. Annotation appearances and anything else reading `llx`/`lly` as the lower-left corner now place such rectangles correctly (#345)
- **A form field whose `/DR` font is a CFF subset got no appearance** — `font::FontEncoder` now checks a subset `/FontFile3` program's glyphs (by glyph name for a simple font, by CID through the charset for a CID-keyed one) instead of refusing it; Type1 subsets are still refused. The renderer's CFF glyph lookup moved to core (`font::cff_simple_glyph`, `cff_cid_to_gid`, `explicit_base_encoding`) and both use it (#341)
- **A list box highlighted nothing for a multiple selection or for an `/Opt` pair whose export value differs from its display text** — `FormField::options` is now a `Vec<form::ChoiceOption>` (`export_value`, `display_value`), `FormField` gains `indices` (`/I`) and `selected_values()` (the options at `/I`, else `/V` as a string or an array), and a list box highlights every selected option and draws display texts. `set_field_value` rewrites a choice field's existing `/I` to match the new value (#346)
- **Multiline and comb text fields were drawn on one line** — `form::appearance::generate_field_appearance` now wraps a multiline field's value into lines as pdf.js does (line breaks honoured, breaking after the last space or before the overflowing character), auto-sizing it so the wrapped lines fit, and draws a comb field (`COMB` with `/MaxLen`) one character per cell. `FormField` gains `max_len`, inherited from parent fields (#332)
- **Text field and combo box values were drawn at a fixed offset, and an auto-sized (`0 Tf`) value was invisible** — `form::appearance::generate_field_appearance` now lays the value out on one line as pdf.js does: an auto size from the text box and the value's width, `/Q` alignment (the widget's, else the field's inherited `/Q`), the baseline centred from the font's ascent and descent (descriptor, else Standard 14 AFM, else pdf.js's fallback), clipped to the text box, inside `/Tx BMC … EMC` with the background and border. Password fields draw no value. `FormField` gains `quadding` (#325)
- **Form field appearances ignored the widget's `/MK` colours and `/BS` width** — `form::appearance::generate_field_appearance` now fills the background with `/MK /BG` and strokes the border with `/MK /BC` at the `/BS /W` (else `/Border`) width, inset by half of it, for every field type. A widget without `/MK` gets no background or border, where every type used to draw a fixed grey or white box with a black border (a push button a grey bevel). Border styles are drawn solid (#333)
- **A filled field's kid widget lost the font, size and colour its own `/DA` set** — `form::set_field_value` now redraws each widget with the widget's `/DA` where it has one, and the field's (inherited) `/DA` otherwise (#347)
- **A filled text field, combo box or list box still showed its old value in viewers that ignore `/NeedAppearances`** — `form::set_field_value` now redraws each widget of such a field from the new value, in that widget's own `/Rect` and the `/DR` font its `/DA` names, and sets its `/AP` to the new `/N` alone (the old `/D` and `/R` are dropped; an indirect `/AP` other widgets may share is left as it was). A widget whose value the font cannot hold, or that has no `/Rect`, keeps its appearance. Checkboxes, radio buttons and push buttons are unchanged (#344)
- **Filling a form field left the old value on screen and could not turn real checkboxes on** — `form::set_field_value` now sets the AcroForm's `/NeedAppearances true`, and writes a checkbox's or radio button's `/AS` on each widget (the value where the widget's appearance has that state, `/Off` otherwise) instead of on the field. `toggle_checkbox` turns a box on with the state its appearance has (e.g. `/On`), where it always wrote `/Yes` (#204)

A stream-dictionary string that does not decrypt is kept as written instead of failing the stream. Encrypted files written by earlier justpdf versions can now read such strings (for example an attachment's `/Params /ModDate`) as garbage, as other readers already did
- **`PdfWriter::set_object` at a new number** — later `add_object` calls could hand out the same number again, so a document carried two objects with one number; when `DocumentModifier` encrypted such a document, the `/Encrypt` dictionary took the number and the other object was written in plaintext. `set_object` now moves the next free number above the one it sets (#75)
- **CLI `encrypt` lost `/Info` and the changing `/ID`** — the command assembled the encrypted file itself, passing no `/Info` and writing the source's first `/ID` element twice. It now goes through `DocumentModifier::set_encryption`, so the document information dictionary survives and the second `/ID` element is new (#75)
- **`DocumentModifier::from_document` on encrypted documents** — an encrypted document that had not been authenticated lost nearly every object silently (every resolve failed), so CLI `encrypt` on an encrypted input exited successfully with a file no reader could open; it is now refused with `EncryptedDocument`. An authenticated one had its old `/Encrypt` dictionary copied along, so `justpdf decrypt` output still carried the old `/O`/`/U` values in plaintext; the dictionary is no longer copied (#75)
- **Encryption randomness and file identifiers** — AES IVs, the AES-256 file key and the R6 salts were derived from the system clock, the random bytes of R6 `/Perms` were zeros, and every encrypted document (`DocumentBuilder` and CLI `encrypt`) got the same `/ID`, so RC4/AES-128 documents with the same passwords and permissions shared one file key. All of these now come from the operating system's random source; `DocumentBuilder` writes a random `/ID`, and CLI `encrypt` keeps the input's first `/ID` element when it has one (#31)
- **Incremental save and signing lost the trailer's document keys** — the new trailer only carried `/Size /Root (/Info) /Prev`, and readers (justpdf, pdf.js, MuPDF) read only the newest trailer, so `/Encrypt`, `/ID` and — when signing — `/Info` disappeared; an encrypted document came back unencrypted with its old objects unreadable. The update trailer now carries every key of the previous trailer. `incremental_save` encrypts the appended objects with the document's key (the modifier must come from an authenticated document) and writes them through the serializer instead of `Display`, which corrupted streams; `sign_pdf` refuses encrypted input (#26, #25 in part)
- **AES-256 R5 password check** — `verify_password_r5` computed the hash and returned `true` without comparing it, so any password "authenticated". Because opening a document tries the empty password first, an R5 file with a user password was locked to a garbage key on open and could not be read even with the correct password. The hash is now compared with `/U` / `/O` (#30)
- **Font subsetting dropped the glyphs it was meant to keep** — `compress_pdf` with `font_subsetting` (medium, high and extreme presets) picked glyphs by treating each character code as a glyph ID, then renumbered them while leaving the font's `cmap` and the PDF's `/CIDToGIDMap` pointing at the old numbers, so embedded TrueType text rendered as blanks even though text extraction still worked. `subset_font` now keeps every glyph ID (unused glyphs become empty; `gid_map` is the identity), glyphs are chosen through the font's own lookup paths, and a font is left whole when its use cannot be fully collected — referenced from a form XObject, an annotation appearance or inherited `/Resources`, or shown with `"` (#51)
- **CI feature-isolation check** — `cargo tree` prints ASCII glyphs on CI, so the script's checks were failing or vacuous; they now match dependency names directly (#62)
- **Encryption round-trip** — binary strings with bytes ≥ 0x7F (e.g. `/O`, `/U`) were written as literal strings and corrupted, so some password pairs produced files that could not be opened. Such strings are now hex-encoded (#20)

## [0.1.4] - 2026-05-08 (justpdf-core)

### Fixed
- **ObjStm `/First` off-by-one** — `load_compressed_object` inferred the
  data-section start from `tokenizer.pos()` after consuming the index
  pairs, which was off by the whitespace padding before the first
  object. Compressed objects' `abs_offset` landed one byte short
  (typically on the previous object's closing `>`), producing an
  `unexpected '>'` parse error. Affected PDFs that use object streams
  with whitespace padding before the data section — common in files
  with incremental updates. Now reads `/First` and `/N` from the dict.
